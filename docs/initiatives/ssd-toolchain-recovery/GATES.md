## Gate applicability and result

For new behavior-changing implementation slices, Domain, Behavior, Spec, Contract,
Test-driven implementation, Refactor and Review/Integrate are required. Deploy,
Operate and Maintain/Retire are required for managed machine changes. Release is
not applicable unless an independently published artifact is actually introduced.
Results remain pending until captured by the owning cycle; deferral/accepted risk
requires explicit user approval. Hibernation is the only newly approved deferral.

Dependency-only work may use the configured lighter maintenance path, but candidate
compatibility, production exclusions, state preservation and validation still apply.
Read-only inventory is not deployment. Do not manufacture green gates from version
output, successful resolution or document existence.

Before registration, commit the owning profile and exact JSON applicability plan,
reference them from the slice, assign concrete writable files and non-overlapping
writers, and encode qualified implementation dependencies in MANIFEST.json.
Do not generate plans bound to nonexistent host/project profiles.

## Available authorities and gaps

- dotfiles: configured pytest, terminal-environment and AI ownership tests, template
  rendering, shell syntax and native package/runtime/service checks.
- dotfiles-ai: configured pytest, relevant Herdr/Lima/distribution/native workspace
  suites, template/plist validation, shell/Swift compilation and native tool probes.
- SDS: project AGENTS.md selects pytest (no xdist), Ruff, mypy, coverage and other
  declared tools; JFrog Xray is sole vulnerability authority when declared. Use
  existing CI/manifest settings, not invented universal tooling.
- Other Python projects: read local instructions/CI/manifests before naming checks.
- GUI, signing, desktop approval and exact-session recovery require live/native or
  operator evidence; substitute neither mocks nor CLI version output.

Run only affected QA. Unavailable configured tools remain an explicit gap; do not
install new QA dependencies to produce a superficial pass. Independent research
can overlap, but shared machine writes and final QA remain primary-owned.

## Compaction-safe completion definition

Every non-deferred material statement has an owner and an implemented, validated,
delivered outcome or explicit unresolved blocker. All managed update candidates
are classified; production exclusions and intentional DVC omissions remain intact.
Recovery history and current state survive. Report hibernation for resumption only
after the rest. Discovery itself finishes when material technical choices are
resolved into source-backed contracts, not when assignments have merely been written.
