# One approval from Discovery to parallel Build

Extend the existing Initiative grant, durable execution store, registration
adapter and managed skills. Expose batch preview and acceptance to ordinary
Plan/Build. Preview the complete selected graph before approval: bind each
slice's source, plan, importable documents, target, worktree, write set,
shared resources, model route, dependency evidence and draft-only intent.
Produce one operator-reviewed receipt. Build verifies it at each mutation;
workers receive only their slice's authority. Protected merges remain separate.

Acceptance: three independent slices in one repository, no existing cycles,
and a shared Discovery branch with unrelated evidence and sibling documents.
Resolve each slice's legitimate inputs locally; prove referenced inputs exist
and keep unowned documents out of publication. An unresolved required input
blocks that slice before approval. Do not change the operator's source branch.
Launch ready workers concurrently only for disjoint claims, verify native
session and model readback, report tab names (or observable session IDs when
outside Herdr), retain dependent work until its condition is verified, and
serialize publication. A repeated Build handoff or process restart reattaches
existing workers without duplicating a cycle or push. Reject overlaps, revoked
or changed grants and scope expansion. Stop on an ambiguous external effect.

Ship through managed source and validate from a fresh or resumed ordinary
conversation. Exercise the three-slice journey on the deployment target after
scoped preview and approved apply. A unit test or instructions alone do not
establish installed acceptance. Preserve ongoing sessions and local edits.
