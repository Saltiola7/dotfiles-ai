# V2 Native Qualification Findings

Informative evidence, not deployment approval. Full qualification remains open.

## Candidate and method

Investigated OpenCode 2.0.21 on macOS aarch64. Published archive SHA-256:
`41caebd166aa1a72bb85c2e9a3ca81c6ff3170af1cbef8b7b07f92f19adb6840`.
Extracted executable SHA-256:
`0b2b68c1efaf20a29aaf636c2ffccc1abb56243a82f48cce45e257d232e03442`.
Publisher-recorded source commit:
`f46fa72a9285a0e8479e25d400f7026bfd8fe5c8`.

Research used isolated HOME/config/data/state/cache/temp roots and a scripted
loopback provider. No hosted inference, operator transcript, live database or
production plugin was used. Native session identities were generated by the
tested runtimes, not supplied as production identities. Private fixture traces
remain outside Git. A fixture success does not qualify production scale or other
platforms.

The synthetic flow exercised successful write, successful foreground shell and
failed read. The shell marker was removed before the native shell command ran.
No admission or lifecycle helper was deployed by this experiment.

The shared-server fixture deliberately reused provider call IDs across two
sessions. Session-plus-call keys kept their completion tracking separate; both
clients exited successfully and shutdown reported zero outstanding markers or
pending calls. Plan-denied write/shell requests produced persisted errors without
writing the fixture. Cleanup on durable failure removed the unconsumed shell
marker. These are bounded cases, not an exhaustive concurrency qualification.

The CLI surface-probe implementation and its bounded CI repair merged through
pull request 191 at `668bb45ff4eb4230a30e6f521bbbb2daec184856`. Required Python
3.12/3.13/3.14 CI checks passed. This does not change downstream readiness.

## Synthetic native data conversion

An isolated verified V1 1.18.31 executable generated one real synthetic session
and four messages. After the V1 process exited, a consistent original database
archive was retained. V2 then migrated and continued that existing session.

| Check | Result |
|---|---|
| Native session ID retained | passed |
| Original message IDs retained | 4 of 4 |
| V2 message count after continuation | 9 |
| Migration checkpoint | completed |
| Original archive bytes unchanged | passed |

This case does not cover compaction transformations, non-inline attachments,
malformed source rows, interrupted migration, pending prompts, background jobs,
large histories or guest conversion. Those remain explicit rehearsal inputs.

## Source findings still requiring qualification

- The V2 shell tool supports backgrounding, including an interactive transition
  of foreground work. A completed tool result can report a still-running shell;
  writer authority must not transfer on that result alone.
- Stock shell creation invokes shell hooks before its tool-specific preparation
  callback adds OPENCODE_SESSION_ID. An inherited environment value cannot supply
  authoritative call identity at the hook boundary.
- The desktop stages its bundled CLI and uses Service.ensure with that version.
  CLI installation through the desktop can also introduce an alternate launcher.
  Desktop service/data-root behavior must be qualified alongside managed CLI
  selection rather than assuming it uses the existing wrapper.
- Native conversion can clear events and legacy permissions and omit malformed
  rows. Completion must be reconciled against retained original evidence.
- The current lifecycle helper and recovery code read legacy session/message
  tables. Their replacement must reject stale legacy authority once V2 owns the
  boundary, while preserving historical evidence and pre-cutover V1 operation.
