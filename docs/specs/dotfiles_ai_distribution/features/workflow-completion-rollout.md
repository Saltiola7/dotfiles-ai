# Completion reconciliation rollout and first-consumer qualification

Owner: distribution maintainer. Profile: [../PROFILE.md](../PROFILE.md).
Product Intent: [../PRODUCT.md](../PRODUCT.md), successful-completion extension.
Risk: critical; modules: Python and Security, plus configured host validation.
Depends on merged lifecycle reconciliation and completion-journey source slices.

## Outcome and scope

Install the qualified helper, shared guidance and any required compatible native
consumer through existing Chezmoi ownership. Then qualify one operator-nominated
stranded cycle using the supported automatic reconciliation route. Consumer
identity, exact checkout, PRs, records and runtime evidence remain private.
This specification grants no present live mutation or consumer success claim.

Source merge, installed version, native availability and recovered completion are
four distinct claims. Verify exact installed/source identities before use. Do not
copy an unmerged helper into production or use its own pending repair as authority
to bootstrap successful closure of its source cycle.

## Qualification and recovery

1. Validate merged dependencies, installed compatibility and source publication
   checks. Inventory the selected target with current read-only supported tools.
2. Obtain one exact scoped deployment/consumer-activation approval, preserving
   existing native permissions. This authorizes installation and the nominated
   recovery workflow, not new merges, cloud applies, deletion or broader recovery.
3. Quiesce incompatible writers through the supported owner. No universal fencing
   is claimed. Preserve existing records, immutable envelopes and Git objects.
4. Apply the bounded managed-source selection, compare installed hashes and test
   supported CLI report/version compatibility and synthetic interruption recovery.
5. Run structural preview first. Resolve unknown provenance through supported
   review; revalidate only affected or genuinely stale acceptance evidence. Never
   claim that historical runtime evidence proves unchanged current production.
6. Invoke ordinary completion with verified segment selectors. Uniquely proven
   reconciliation runs automatically without another bookkeeping consent prompt.
7. Verify completed state, effective requirement coverage, retained historical
   failures, exact PR provenance, idempotent retry and historical reading.
8. Keep checkout, branch and data. Cleanup remains separately selected and approved.

If a prerequisite or proof is unavailable, preserve the active cycle and return
the classified blocker. Do not label it retired to obtain a terminal state.
Rollback stops new admission and restores only a compatible reader/writer set;
never erase new custody or use an old incompatible writer against it. No guest
fleet rollout or second nominated cycle is implicitly authorized.

## Gates and validation

Use a dedicated distribution rollout applicability plan: kernel, Review/Integrate,
Deploy, Operate and Maintain/Retire required; Release N/A because no independent
package is published. Reuse configured render and installed-identity checks,
Python/CLI tests and native route smokes. No replacement installer or credentials.

Success: nominated cycle truthfully completed through public CLI with all effective
obligations accounted for; old evidence retained; second identical invocation has
no new effects; zero worktree/branch/data removals and zero rewritten Git history.
Blocked runtime checks are retained failures, not conditional passes. Consumer
availability is evaluated at rollout, not fabricated as a source-slice dependency.
