# Optional integration coordinator distribution and rollout

## Intent and ownership

The [delivery amendment](../../../initiatives/dbsctr-delivery-lifecycle/INTEGRATION-COORDINATOR.md)
and [lifecycle contract](../../dbsctr_v3_lifecycle/features/integration-coordinator.md)
own one portable integration protocol. Distribution owns compatible installation,
personal policy and hosted enrollment. This Discovery does not install modules,
export credentials, initialize remote state, change protections or activate jobs.
The existing Engineering Profile and Product Intent apply with critical risk.

Users retain concurrent coding and separate phase-preserving PRs. An explicitly
enrolled repository uses one active final candidate independently of the user's
computer. Shared defaults stay disabled; personal and repository/task overrides
preserve draft, ready, normal merge and exact-repository review-exception modes.
The first rollout covers new cycles plus explicitly selected existing PRs.

The operator now authorizes finishing and activating the two selected repository
targets. The [runtime amendment](../../dbsctr_v3_lifecycle/features/integration-runtime-adapters.md)
consolidates shared lifecycle/native/policy source. Its schema-2 delivery table
extends the existing policy owner; no global enablement or silent migration is
introduced. Installation and exact hosted qualification still follow merged source.
Explicit credential delegation remains required; this authorization does not copy
local credentials or confer a human review exception on another identity.

## One compatible owner

Use the existing repository-policy and managed-generation owners, with an explicit
new capability/version. Do not silently widen delivery schema 1 or add another
policy file, daemon, credential owner or result ledger. One installed generation
binds the shared Python package, thin entrypoint and lifecycle hook together.
Hosted jobs consume the same reviewed source pin and per-repository configuration;
consumer copies of the state machine are forbidden. A stale canonical checkout
must not downgrade the accepted helper, package or unrelated validation guidance.

The proposed shared package is
`private_dot_config/dotfiles-ai/integration_coordinator/`, with
`dot_local/bin/executable_dbsctr-integration` as its thin source entrypoint.
Source delivery precedes installed availability. The source-only core slice
cannot submit live requests, read local credentials or use enabled enrollment.
Existing lifecycle state and narrow rebased-completion APIs stay authoritative
until their separately qualified hook/receipt amendment is delivered.

## Staged activation contract

| Stage | Required evidence and mutation boundary |
|---|---|
| Source draft | New package/entrypoint, deterministic fixtures and proposed interfaces; existing hooks, policy, CI and runtime unchanged |
| Lifecycle/policy source | Qualified SourceSeries/adoption/receipt hooks and compatible versioned existing policy; serialize with concurrent helper work |
| Managed installation | Exact merged source, scoped rendered diff, generation verification and rollback retaining compatible readers; preserve unrelated files and Dagger guidance |
| Repository enrollment | Approved exact native repository/default target, allowed requester and merge identities, state branch, check plan, workflow source pin and finite bounds |
| Hosted credential qualification | Independently enrolled least-privilege identity; prove source-refresh PR CI and post-merge triggers plus native review-exception/freshness semantics |
| Operate | Durable admission, scheduled recovery, uncertain native mutation reconciliation, original-task feedback, disable and same-slot operator recovery |

Activation is target-bound and now in the operator-authorized scope. Source tests do not prove a
hosted identity, repository exception or unattended delivery. An Actions token
never inherits a person's review exception. Never copy a credential automatically
from local configuration. Missing enrollment or state is unavailable/disabled,
not an instruction to initialize or repair remote state.

Existing CI triggers, checks and native platform obligations remain intact.
Dagger stays a separately enrolled default-off shadow pilot. This feature does
not start its engine, alter admission budgets, accept cached/signed passes or
change native check authority. Other throughput and typing work keep their owners.

## Disable, recovery and retirement

Disabling admits no new requests, preserves accepted tickets and source evidence,
and reconciles any owned uncertain mutation before surrendering custody. Do not
kill an unknown merge actor and immediately authorize another. Revoked credentials
leave an explicit blocker; the same active slot can be resumed by a qualified
operator with fresh guards. Degraded recovery requiring that operator cannot
claim offline unattended delivery.

Remote delivery and local lifecycle completion are separate. A hosted receipt
never authorizes deletion. The original retained checkout consumes qualified
rebase correspondence and preservation evidence before existing retirement rules
can apply. Rollback retains compatible readers, ledger history, local mappings,
original phase commits and unresolved delivery/repair obligations. No automatic
branch/worktree deletion or remote history rewriting is added.

## Qualification

| Case | Required result |
|---|---|
| Fresh/shared defaults | No credential access, state branch creation, submission or worker activation |
| Selected repository/task | Only exact enrolled identity/target and authorized delivery mode apply |
| Existing PR without adoption | Ignored; neither label nor prior green CI creates lifecycle authority |
| Stale source/installed generation | Refuse downgrade/conflict and preserve current guidance and unrelated files |
| Absent/revoked hosted identity | Preserve ticket and report non-unattended same-slot recovery |
| Candidate/policy drift or missing native evidence | Invalidate current qualification; no bypass or fabricated pass |
| Disable during uncertainty | Keep custody and reconcile native outcome before another mutator |
| Local agent asleep | Green qualified work can merge only through proven hosted authority; repairs and local receipt consumption wait |
