# DAI-023 Conditional Lima Home

## Behavior

- Given a configured workspace, when the operator requests `start` or `stop`,
  the controller invokes that exact lifecycle action for only the declared Lima
  instance.
- Given an unknown workspace, the controller fails before invoking Lima.

## Contract

- `sandbox-vm start WORKSPACE` invokes `limactl start INSTANCE` with a 120-second
  bound.
- `sandbox-vm stop WORKSPACE` invokes `limactl stop INSTANCE` with a 120-second
  bound.
- Workspace names resolve only through the validated machine-local registry.
- Status allocation reads the configured Lima home, or `~/.lima` when the
  machine-local setting is empty.
- Configured lifecycle actions and temporary federated-review transitions share
  one per-instance lock, so review restoration cannot undo an operator action.
- Effective home precedence is configured `lima_home`, inherited `LIMA_HOME`,
  then `~/.lima`; both allocation and free-space status use that filesystem.
