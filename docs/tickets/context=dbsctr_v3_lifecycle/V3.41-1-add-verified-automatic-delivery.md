## Outcome

An explicitly enabled DBSCTR cycle can merge only its exact tested pull-request
head, converge a compatible base checkout, and retire its clean isolated
worktree without weakening disabled-by-default behavior.

## Context

Final Push currently stops at a draft pull request, marks the cycle complete,
skips source synchronization, and permits time-based cleanup without proving the
pull request merged. Operators must manually reconstruct branch and worktree
state after delivery.

## Scope

Implement the disabled-by-default policy parser, ready pull-request delivery,
protected auto-merge request, check-gated exact-repository administrator merge,
verified-merge reconciliation, base fast-forward, and cleanup ordering defined
by the automatic-delivery specification.

Do not render Chezmoi policy, schedule unattended maintenance, manage Herdr
panes, support squash/rebase merges, or mutate existing records without an
automation snapshot.

## Acceptance Criteria

- Missing or disabled policy preserves draft pull-request behavior.
- Every merge request is bound to the exact expected head.
- Administrator merge requires an exact configured repository and fresh passing
  required-check evidence.
- Merge commits contain every recorded Gate Commit before local reconciliation.
- A compatible Base Checkout fast-forwards before clean worktree cleanup.
- Dirty, diverged, current, changed, ambiguous, or unmerged work remains intact.
- Repeated maintenance is idempotent and existing Cycle Records remain readable.

## Risks

Incorrect GitHub-state interpretation could bypass protection or remove
recoverable local state. Exact-head guards, required-check validation, merge
ancestry, fail-closed parsing, and focused regression tests constrain the risk.
