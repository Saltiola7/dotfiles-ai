## Outcome

DBSCTR begins protected-branch pull-request cycles without retrying delivery or
repository arguments, and Final Push uses the GitHub account recorded by the
cycle instead of the ambient active account.

## Context

Recent Build telemetry showed repeated `dbsctr_begin` failures when callers used
`merge` for pull-request delivery or supplied a bare repository name. Completed
cycles then repeatedly failed Final Push because Git used another active GitHub
account even though the Cycle Record named the intended account.

## Scope

Normalize protected `merge` begin requests to `draft_pr`, derive the canonical
repository from `origin`, reject upstream mismatches before network or worktree
changes, and bind the selected account token to draft-PR Git and GitHub operations.

Do not infer an account, expose tokens, weaken protected-branch guards, change
low-level `start`, alter persisted schemas, or deploy managed configuration.

## Acceptance Criteria

- Protected `merge` begin requests become `draft_pr` before remote access.
- Ordinary typed begin preserves an explicit protected base; Initiative launch
  binds the target repository's default branch.
- Omitted or matching bare repository input resolves to canonical `owner/repo`.
- Mismatched input, fetch, or push repositories and invalid accounts fail before
  fetch or worktree creation; credential-bearing remotes and URL rewriting fail
  closed.
- Other non-PR delivery to the protected branch still fails closed.
- Draft begin and Final Push use the recorded account without changing the global
  active GitHub account or accepting ambient SSH and credential-helper identity.
- Tokens remain process-local and absent from arguments, output, Git, and Cycle Records.
- Existing low-level start and historical Cycle Records remain compatible.

## Evidence

The two focused regressions failed before implementation: protected begin had no
normalizer, and a token-requiring remote rejected Final Push. Affected QA passed
249 tests with one expected skip; advanced-target union QA passed 412 tests with
one expected skip. Python compilation, Bun bundling, Git whitespace, and
source-identical Chezmoi rendering passed.

## Risks

Incorrect normalization could weaken required gates or target another repository.
The implementation limits normalization to `merge` against the declared protected
branch, preserves the plan's explicit gates, derives repository identity from the
configured GitHub origin, and rejects mismatches.

## Review

Independent correctness/security review found account-binding, upstream-binding,
ambient Git configuration, and low-level compatibility gaps. Remediation added
canonical HTTPS transport, explicit credential isolation, rewrite rejection,
custom-base forwarding, and legacy `start` preservation. Final review found no
remaining production issue; one test-precision finding was corrected before QA.
