## Outcome

Feature cycles can prove selected Graphify output without mutating canonical
artifacts, while integration owns one receipted graph-only promotion commit and
separate DVC publication evidence.

## Context

Project-owned Graphify adapters needed fixed-commit lifecycle execution without
granting feature cycles authority to mutate canonical graph artifacts or publish
DVC state.

## Scope

Bind project-selected adapters to cycle plans, execute checks in disposable
worktrees, retain private receipts, and reserve canonical graph promotion and DVC
publication for the integration workflow.

## Acceptance Criteria

- Applicability plans strictly bind an optional committed adapter and version.
- Feature checks run at exact HEAD in disposable worktrees and retain private receipts.
- Final Push rejects absent, altered, or stale selected receipts.
- Batch finalization closes admission and changes only canonical `graphify-out/`.
- DVC-relevant publication requires evidence bound to the graph commit.
- Fixed-commit audit accepts only verified graph-only descendants or tree-neutral merges.

## Risks

Executable project adapters and graph/DVC identities cross local trust and
publication boundaries; validation fails closed and external writes remain
separately authorized.

## Review

Review rejects stale adapter identities, feature-cycle canonical graph writes,
unreceipted promotion, and DVC publication without separately recorded evidence.

## Evidence

Affected QA passed 163 helper tests with one existing skip, 68 lifecycle and
control-plane tests, Python compilation, Git diff checks, targeted managed
deployment/idempotence, exact deployed source identity, and final independent
review with no blockers. Gate Exceptions: none.
