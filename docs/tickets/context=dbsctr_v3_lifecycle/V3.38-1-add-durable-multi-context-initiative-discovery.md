## Outcome

Broad multi-repository intent becomes a durable, validated Initiative before
implementation, and ready slices can enter approved DBSCTR cycles while the
coordinator continues discovering the remaining fleet.

## Context

Current Discovery is single-context and keeps interview state volatile until a
late Build handoff. Repeated compaction can omit requirements, start Build before
the specification fleet is complete, and drift across repositories.

## Scope

Add the Initiative manifest and readiness contracts, separate-profile support,
compaction reanchoring, current Herdr session-fork orchestration, docs-only
Discovery operation, specification-ready ticket handoff, and focused validation.

Do not bulk-migrate existing contexts, retain raw transcript copies, make Jira or
Herdr authoritative, or automatically approve Build, release, or deployment.

## Acceptance Criteria

- Every material statement has stable identity, disposition, and coverage.
- User-approved context homes and dependency-safe slices can run independently.
- Ready slices require complete artifacts, stable tickets, and exact approval.
- Compaction reloads durable context and cannot authorize stale readiness.
- Current Herdr 0.8.2 syntax launches a fork or safe fresh-session fallback.
- New or materially revised contexts may use `PROFILE.md`; existing README-based
  profiles and active Cycle Records remain valid.
- Late material intent reopens affected readiness and dependent promotion.

## Evidence

Discovery interview decisions are persisted in the Initiative manifest and
normative feature specification. Implementation and runtime evidence remain
pending.

## Risks

This changes global lifecycle routing, permission boundaries, compaction context,
Git artifact validation, and local session launching. Inputs fail closed, Herdr
remains advisory, and external writes retain existing approvals.

## Review

Implementation readiness reached after the user approved the Initiative model,
artifact boundaries, session tree, research routing, concurrency policy, ticket
stability, and exact Build approval boundary.
