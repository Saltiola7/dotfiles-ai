## Outcome

DBSCTR uses one managed, digest-bound Graphify adapter for every selected project;
target repositories contain no Graphify adapter implementation.

## Context

V3.37-1 required each project to commit executable adapter code. The first
downstream implementation showed that runtime isolation, DVC handling, path
safety, cache reuse, output validation, and atomic publication are reusable
lifecycle mechanics. Duplicating that security-sensitive code in each repository
creates competing authorities and divergent fixes.

## Scope

Replace repository-relative adapter selection with a bounded Graphify version.
At cycle start, bind that version to the exact managed central adapter digest.
Use the same central adapter for disposable checks and batch finalization. Keep
project source, `.dvc/config`, and canonical `graphify-out/` local to the target;
do not add project scripts, remote writes, automatic graph selection, a daemon,
or a second cache manager.

## Acceptance Criteria

- Applicability plans select Graphify with exactly one bounded `version`; project
  adapter paths and blobs are rejected.
- Cycle records and graph receipts bind the managed adapter SHA-256 and selected
  version, selection remains monotonic, and a private content-addressed snapshot
  keeps active cycles and batches executable across managed adapter upgrades.
- The managed adapter validates exact runtime additions, sanitized execution,
  owner-controlled paths, symlink-free graph/cache trees, graph/report identity,
  bounded canonical files, DVC staging scope, and cache counters.
- Missing local DVC objects may use only a primary canonical graph with an exact
  committed pointer size/MD5 match; mismatch fails without remote DVC access.
- Checks run at exact HEAD in a disposable worktree and atomically publish only
  private bounded output; finalization updates only canonical `graphify-out/`.
- Failed finalization restores the exact canonical graph tree and Git index baseline
  after update, validation, DVC staging, or contamination failures.
- The adapter never performs DVC pull/push, Git push, publication, provider
  requests, service deployment, or automatic canonical promotion.
- Generic fixtures prove warning-bearing versions, uv virtualenv execution,
  missing local DVC failure, unsafe source/cache paths, check publication, and
  finalize contamination behavior without repository-owned adapter code.
- Existing schema-1 graph receipts remain auditable; new receipts identify the
  managed central adapter contract.
- The managed helper and lifecycle skill deploy idempotently, and one disposable
  external project smoke passes without changing that project.

## Risks And Recovery

Central code now crosses every selected repository's local graph and DVC boundary.
Exact adapter/runtime identity, no-follow validation, offline DVC commands,
bounded output, and separate DVC publication approval contain the risk. Rollback
restores V3.37-1 helper and skill files; target repositories require no revert.

## Evidence

The closed downstream PR remains implementation evidence only; no downstream
commit reached its protected base branch.

Scoped QA passed 280 tests with one existing skip. Targeted managed deployment
was source-identical and idempotent. A detached external exact-HEAD smoke generated
24,161 nodes, 42,369 links, and 2,004 manifest files using local-only DVC recovery,
then removed its disposable worktree and output. Final independent review found no
high or medium issues; no Gate Exception or DVC push was required.
