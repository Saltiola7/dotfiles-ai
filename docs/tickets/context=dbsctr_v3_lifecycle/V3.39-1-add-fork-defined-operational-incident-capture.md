## Outcome

Operators preserve one live DBSCTR operational case as one OpenCode fork, review
automatically gathered failed-call signals without interrupting feature work,
investigate with bounded redacted evidence, and link one separately owned fix
cycle.

## Context

Current lifecycle review retains aggregate failure counts but has no operator-
defined case boundary, category diagnostics, source-local evidence record, or
verified link from a reported operational problem to its activated fix.

## Scope

Add a source-local Incident inbox, explicit fork registration, category-specific
diagnostics, lifecycle updates, evidence forgetting, typed adapters, and review
presentation. Reuse persisted OpenCode state and the private review ledger.

Do not add live event hooks, automatic forks, a service, raw cross-workspace
federation, model scans of successful turns, or automatic remediation.

## Acceptance Criteria

- Persisted failed tool parts produce read-only bounded Incident Signals across
  the existing DBSCTR review family; recovered failures remain at lower priority.
- `/incident` registers only a child session, confirms one kind and `INCIDENT:`
  title, captures bounded redacted evidence and diagnostics, and promotes selected
  signals atomically.
- `/dbsctr-review` presents registered Incidents, then automatic signals, then
  ordinary review candidates without changing ordinary review markers.
- One Incident links at most one fix cycle and resolves only after completed
  required Deploy and Operate evidence.
- Explicit forget removes Incident Evidence without deleting the OpenCode fork or
  allowing forgotten signals to reappear.
- Existing review, history, federation, backup, restore, and privacy integrity
  remain compatible.

## Evidence

Affected QA passed 247 tests with one expected skip, Python compilation, Bun
bundling, and Git whitespace validation. Reconciliation with the advanced target
was conflict-free; its additional affected suites passed 112 tests. Targeted
Chezmoi deployment is source-identical and idempotent, the live configuration
parses, the deployed helper exposes `incident-scan`, and the live tool bundle
passes. Independent review findings covering restore anti-resurrection, redaction,
authority binding, canonical fix evidence, bounded scans, and permission policy
were remediated and verified. Gate Exceptions: none.

## Risks

Tool errors and diagnostics can contain credentials or private environment data.
The source-local ledger and typed output must redact before persistence, remain
bounded, serialize writes, and fail closed on malformed or ambiguous authority.

## Review

Primary and independent review confirmed the committed Incident contract and
regressions. Same-user agents with unrestricted shell remain trusted to respect
declared ownership; command policy is not OS privilege separation.
