# Reader-First Structural Method

Use these checks to discover and test an argument. They are not mandatory output
headings.

## Establish Relevance With SCQA

- **Situation:** stable context the intended reader can accept.
- **Complication:** change, tension, failure, or opportunity that makes a response
  necessary.
- **Question:** the single question the complication raises for this reader.
- **Answer:** the governing message that resolves that question.

Omit or compress elements the reader does not need. SCQA establishes relevance;
it is not a fixed prose template.

## Test The Levels

### Vertical question-answer logic

Read from the governing answer downward. Each statement should raise a natural
reader question such as why, how, or what. The level below must answer that
question. Read upward and verify that the parent accurately summarizes its
support rather than merely naming a topic.

### Inductive groups

Use an inductive group when sibling points are the same kind of thing: reasons,
actions, risks, findings, or options. Name that shared class, remove overlaps,
find material omissions, and write a parent summary that states what the group
means rather than listing it again.

### Deductive chains

Use a deductive chain when one statement, a related statement, and their
implication must be understood in sequence. Make every inference visible enough
for the audience and ensure the conclusion follows. Do not mix an inductive list
into the same sibling group.

## Choose Logical Order

Order siblings according to the reasoning that formed them:

- argument order for a deductive chain;
- time or causal order for a process;
- structure order for parts of a whole;
- importance order for ranked members of a class.

If none applies, the grouping probably needs revision. Do not claim exhaustive or
non-overlapping coverage without testing it against evidence.

## Construct And Verify

### Top-down construction

Use when the governing answer is known: define the reader and question, state the
answer, identify the next question it raises, then support it with one coherent
group. Repeat only to the depth the reader needs.

### Bottom-up construction

Use when notes or evidence exist without a stable answer: extract distinct
claims, group like claims, state the implication of each group, and repeat until
one governing message emerges. Challenge evidence that fits no necessary group.

For either direction, test each summary by comparing it with every child. Mark
unsupported claims, conflicting evidence, and inferential leaps. The final
artifact leads with the answer appropriate to its genre, while the logic map
makes the support and uncertainty inspectable.
