# OpenCode native ownership

Resolve the actual OpenCode executable/version, effective native configuration
layers and existing source/merger owner. For native V2 the server map is
`mcp.servers`; disabled state uses `disabled:false` for an enabled entry. Follow
the selected version's actual command/args/environment schema and native writer
rather than importing the legacy `mcp.<name>` / `enabled:true` command-array
example. Do not infer auth-store paths or edit an old `mcp-auth.json` directly.

A dotfiles-ai managed entry belongs to its existing V2 template/merger; preserve
native Code Mode and unrelated servers/settings. Inspect exact same-name identity
and retain private preimages before an authorized change. Global, override and
project layers must be resolved through their actual owner; do not create another
file, retarget a URL to the CLI default or change a global owner to obtain success.

For a selected JFrog-governed stdio route, retain the reviewed Agent Guard
version/registry, actual platform ID and inspected package. Route non-secret
project/package identity through supported `_JF_ARGS`; use native secret references
and actual forwarding controls for inputs. A Gateway route needs an inspected
supported route and native remote transport. [Common preflight](agent-guard-common.md)
applies; generic MCP tasks remain with their independent owner.

Native entry/configuration presence, connected process, authentication, returned
upstream tools and successful target operations are different observations. Native
OAuth owns login; `enable_*_tools` starts authentication and is not a read-only
probe. Do not enable/restart/login, rewrite credentials or bypass policy as an
automatic verification step. Report denied/missing capabilities honestly.
