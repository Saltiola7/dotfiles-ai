# Inventory or retire installed catalog plugins

Use only the explicitly selected JFrog catalog/platform/project and existing
native source/install owner. Cover the base JFrog guards once; retain actual
errors, requested versions and project-required scan/provenance gates. Agent
Guard is a separate reviewed runtime: examples use a qualified owner-selected
executable/pin, never floating npx installation. Listing can execute downloaded
code; no tool installation or authentication follows from loading this file.

Use the actual native client/plugin owner's inventory for requested scope;
local and global plugin stores can differ. Distinguish installed files, registered
plugin, enabled hooks/runtime and live functionality. Do not claim unexamined
scopes or infer provenance from a folder name.

Resolve exact plugin/version, affected files/hooks/configuration and dependent
callers before authorized removal/disablement. Use that owner's supported native
writer rather than `rm -rf` or whole-cache deletion. Preserve unrelated entries,
shared runtime dependencies and authentication, retain private preimages and
verify actual native absence/disablement. A plugin's removed files do not prove
all processes stopped; restart/operations retain their native owner and scope.
