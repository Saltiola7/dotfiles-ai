# Install or update a selected catalog plugin

Use only the explicitly selected JFrog catalog/platform/project and existing
native source/install owner. Cover the base JFrog guards once; retain actual
errors, requested versions and project-required scan/provenance gates. Agent
Guard is a separate reviewed runtime: examples use a qualified owner-selected
executable/pin, never floating npx installation. Listing can execute downloaded
code; no tool installation or authentication follows from loading this file.

Resolve concrete plugin slug/version/repository, review root `plugin.json`, full
resources, provenance and applicable security evidence, and identify the actual
native client/source owner. A catalog plugin can install hooks, configuration or
runtime code; skill installation alone never authorizes that broader effect.
Do not overwrite an existing same-name entry, change providers or enable hooks
under another owner's configuration.

If the selected native JFrog CLI owns this plugin install, inspect actual
`jf agent plugins install/update --help`, pass the concrete repo/version/server
and retain preimages/true child status. A selected mutable alias requires concrete
resolved version/bytes before a provenance claim. Otherwise implement through
the existing managed source/native plugin owner. Verify files, native discovery,
hook/runtime effects and task behavior as distinct observations.

Missing attestation is a real provenance gap. Do not set
`JFROG_AGENT_PLUGINS_DISABLE_QUIET_FAILURE=true` as an ordinary retry, on generic
consent or to make an installation pass. Preserve required signatures, scans and
release controls; any actual qualified exception follows the project's explicit
process. Denied/pending/failed evidence remains visible. Never switch repositories
or platforms, auto-provision one or bypass a gate to obtain success.
