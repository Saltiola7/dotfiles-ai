# Inventory or retire installed catalog skills

Use only the explicitly selected JFrog catalog/platform/project and existing
native source/install owner. Cover the base JFrog guards once; retain actual
errors, requested versions and project-required scan/provenance gates. Agent
Guard is a separate reviewed runtime: examples use a qualified owner-selected
executable/pin, never floating npx installation. Listing can execute downloaded
code; no tool installation or authentication follows from loading this file.

Inventory only the requested actual scope using its native owner. Distinguish
workspace, user/shared and plugin-owned copies; do not blindly scan all homes or
assert a CLI list is native-client discovery. Keep exact slug, version,
repository, files and source owner where observed, and mark unknown identity.
Reading metadata can reveal private identifiers; bound output accordingly.

For removal/disablement, resolve the exact selected installation, its native
owner, dependencies and any surviving discovery copies. Preserve unrelated skills
and credentials. A dotfiles-ai managed skill is changed/retired in source and
reviewed exact-target deployment; do not recursively delete its shared directory
from a catalog recipe. Retain private preimages/rollback and verify native
absence/disablement separately. No automatic plugin, cache or authentication
cleanup belongs to a selected skill removal.
